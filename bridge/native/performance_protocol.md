# Performance controller protocol

Matched Audio/MIDI catalog implementation, selected explicitly with `--audio-performance` and the corresponding `live/PerformanceController` adapter. The accepted UX is in [lightpad/UX.md](../../lightpad/UX.md). Device owns contacts, gestures, patch context, mixer/recording views, local optimistic values and animation. Live owns actual musical facts. Bridge keeps latest received device intent separate from confirmed facts, coalesces replaceable values and transports bounded commands. No Native objects leave Live callbacks. Programs, helper and adapter form one matched contract; the normal controller path remains available independently.

## Device intents

Channel1 CC frame, all data7-bit: `69 generation,70 sequence,71 key,72 low7,73 high7,74 matching-sequence`. Wrong generations are discarded before admission. Sequence is device-global modulo128. Entire frame must be valid before acting. Value is low7 | high7<<7. No raw contacts travel through Live. Parameter moves coalesce locally at40ms and always flush final value.

- key0..47: group*6 + control, absolute0..127; control0 volume,1 pan,2..5 the four assigned parameters.
- keys48..55: low13 bits of each group assignment, value0..8191. Keys116..123 carry the corresponding high12 bits, value0..4095. The full mask selects up to25 Audio or MIDI descendants of the unique `[Inputs]` hierarchy in current Live order; organizational subgroups are flattened. Each bank is independently replaceable and its ACK echoes only that admitted subset. Updating one bank preserves the other. This changes future takes and selects the group for monitoring; readiness is separate.
- key57: monitor owner, absolute group0..7. This changes live-input monitoring without changing assignments.
- key58: internal allocation grant, value1..16382. The device sends the current busy ticket only after showing its busy overlay and all existing contacts have lifted. This is framed, generation-checked and acknowledged through the ordinary command path; it is never a musical gesture or an automatically replayed mutation.
- key56: toggle mute batch, value is8-bit group mask. One discrete transaction, all toggles at last release. Device previews its future mute state immediately. Ack value is actual muted group mask.
- key64..103:64+group*5+action; action0 Begin,1 Accept,2 Retry,3 Accept+Next,4 Cancel.
- Recording value low7 is current session token. Begin chooses a new token. Retry/Next value high7 is the next token, so a stale control cannot act on a replacement. Accept/Cancel high7 is zero. Token0 is legal.
- key112: Tap Tempo, discrete value0. key113: Click, absolute desired0/127. keys114/115: absolute numerator1..99 and denominator1/2/4/8/16. Their ACKs report actual values.
- Channel16 CC106 reports local held-contact count, CC107 reports local recording/pending-record UI busy, CC108 reports model-ready34main/35metronome/37patch, with36 reserved for the status program; CC110 value19 requests fresh cached model after program initialization. No raw contact stream goes to Live.
- key104..111: Clear that group, value0. Stop its playing clips and advance to next free phrase row, preserving clips. This is discrete.

Mixer, patch-mask, monitor-owner and meter intents are replaceable per key. Rapid patch retaps replace the affected desired bank instead of queuing toggles. The bridge drains both pending assignment banks before Begin for that group. Ending contacts or leaving the patch screen does not cancel an admitted request. Local ownership and pending intent protect its preview while readiness catches up. Discrete operations preserve order, deduplicate sequence+key+value within their bounded lifecycle, never replay an uncertain recording action. No automatic recording intent replay after reconnect. A full discrete queue fails explicitly; it never grows unbounded or silently drops a transaction. Gesture cancellation and view ownership stay local.

## Bridge/Live MIDI

Use the existing stable virtual ports, with explicit Native MIDI forwarding like OptimisticFaderSpike. Channel16 CC78 generation explicitly establishes a fresh bridge protocol session and is echoed by Live onCC79. It clears Native wire duplicate/observation sequence state and reseeds actual facts, preserving musical takes. This works even when a new helper process reuses a7-bit generation. Once warm, periodic CC79 is a keepalive that must not reset a healthy flight. Facts before the accepted session handshake are ignored. Each bridge command is channel1 `69 generation,70 wire-sequence,71 key,72 low7,73 high7,74 matching-wire-sequence`.

Live replies channel1 `69 generation,75 wire-sequence,76 key,77 low7,78 high7,79 matching-wire-sequence`. Parameter ACK value is actual value. Patch-bank ACKs echo the admitted13-bit or12-bit subset and monitor-owner ACKs echo the selected owner; neither waits for background preparation. Discrete accepted value0, except mute batch returns actual muted mask. Value16383 means rejected/failed. Retain the last completed wire command/reply to make duplicate frames idempotent. Reject mismatched generation/sequence/context. ACK is command admission/execution result, not proof recording has started.

One short command can be in flight. Prioritize discrete commands over pending parameter keys; coalesce each parameter key. A timeout reports uncertainty and does not retry a discrete mutation. Native mutation durations and command queue age are separately measurable. Preparation never runs inside receive_midi.

Live facts use a separate channel1 observation frame: `89 generation,90 observation-sequence,91 kind,92 a0,93 a1,94 a2,95 a3,96 b0,97 b1,98 b2,99 b3,100 matching-observation-sequence`, where a,b are unsigned28-bit values packed into four7-bit chunks. Malformed frames publish nothing. Kinds/payloads match the device messages below. Each observation is atomic. Emit changed facts, bounded clocks; do not send a whole-Set snapshot per touch. Discover/cache targets separately. Reconnect emits one bounded fresh model.

## Atomic bridge to device messages

SDK `handleMessage(a,b,header)`. Header low8=0xF2; bits8..10 kind0..7; bits11..17 generation1..127; bits18..30 model revision modulo8192. Every packet has a newer revision in the same generation; distance1..4095 is forward. Kind0 seeds a new generation. Other generations are ignored until seeded. Revision alone never permits overriding newer or active local intent.

- kind0 seed: a=last admitted device sequence,127 if none; b=0. A newly initialized program resumes its next sequence from a. An ongoing program must not rewind sequence on a same-generation reseed. Keep ongoing device gestures, safe desired parameter values, and resend the latest pending parameter intent after seed. Clear ambiguous discrete intent instead of replaying it.
- kind1 actual parameter: a=key0..47, b=actual0..127 or128 unavailable. Unavailable is visiblyzero and blocks new local drags; it is not reported as an actual minimum. The bridge gates Groupavailable until all six initial parameter facts, including128 sentinels, were sent, and resets that gate on reseed. Update confirmed fact; apply to visible value only without local ownership/outstanding newer intent.
- kind1 assignments: a=48..55, b=the full25-bit currently admitted desired mask for that group. High-bank keys116..123 have no separate observation address. The bridge splits confirmed bank caches from this fact and merges a bank ACK into only its corresponding bits. Independent per-bank sequences and serials protect newer retaps. A preparation failure can later publish a rollback; keep each newer local bank until its matching acknowledgement.
- kind1 monitor owner: a=57, b=owner0..7, or8 when no unique owner exists. Eight is an observation-only sentinel, never a valid monitor intent or successful owner ACK.
- kind2 ACK: a=key | device-sequence<<7, b=actual/status. A matching latest ACK releases that intent. Stale ACK must not overwrite a newer intent. Rejection causes the established brief local failure feedback, without closing another take.
- kind3 group facts: a=group0..7; b bits0..20 RGB7 channels at0/7/14; bit21 available; bit22 populated; bit23 muted. Mute previews survive older facts until matching batch completion. Unassigned groups blank. Unavailable group gesture flashes locally.
- kind4 clock: a=group0..8 | span-in-quarter-beats*256<<4, b=position-in-quarter-beats*256. Group8 is the real global bar. Span and position max21bits; clamp actual display range, do not reinterpret a long loop as a one-bar loop. Global clock drives bar pulses and metronome. Live sends global roughly5Hz and visible refs at most2Hz; device interpolates with tempo.
- kind5 take facts: a=group bits0..2 | token bits3..9 | phase bits10..12 | captured-bar-length*16 bits13..25; b=measurement-in-quarter-beats*256. Phase0 idle,1 preparing,2 countdown,3 actually recording,4 pending finish,5 failed. Countdown measurement is remaining beats to actual scheduled target; recording/finish measurement is elapsed beats since actual start. Use actual start/meter metadata. Device calculates accepted8-bar dots/pages, fade and reverse countdown locally. Only matching group/token facts govern the current recording view. Pending finish keeps the view until actual completion, then overview; Next transitions to its replacement token without closing, including a phase5 failure that arrives before any intermediate replacement fact; its prepared start shares the old take's finish boundary. Preparing has no invented actual countdown target.
- kind6 global facts: a=0, b=tempo*128. For a=1, b=numerator | denominator<<7 | running<<14 | click<<15 | recordable-group-mask<<16 | (monitor-owner+1)<<24. Recordable-group-mask occupies bits16..23 and requires a nonempty assignment with available sources. Monitor-owner occupies bits24..27 as1..8; zero means no unique owner. The fixed-source configuration publishes mask255 and owner0. a=2 remains reserved for transport/health flags. Tempo/meter reflect actual Live state; consumers must mask denominator and flag fields independently of the upper Audio bits.
- kind6 allocation busy: a=3, b=ticket1..16382 to request a temporary input pause, or0 to clear it. Bridge retains and prioritizes this fact for every program, including reseeds and failed-send retries. A successful SDK send is not a device acknowledgement.
- kind6 readiness: a=8+group0..7, b=prepared25-bit-mask | busy<<25 | failed<<26. Desired state is the separate full kind1 assignment fact. A mask ACK alone must not stop the pending pulse. The patch client's upper input row shows its local desired state and its lower row pulses between prepared and desired states. Failure rolls back the still-current intent to its prior confirmed patch and flashes briefly; it must not overwrite a newer revision.
- kind6 source metadata: a=24..48 for catalog slots0..24; b bits0..20 contain RGB7 at0/7/14, bit21 marks availability, bit22 identifies a MIDI source, bits23..25 carry its owner group0..7 and bit26 says that owner exists. Empty slots publish zero. The patch program requires all25 metadata facts before announcing model-ready. Ownership and availability are confirmed Native facts, separate from a pending assignment preview.
- kind6 source names: a=64+source*8+chunk, with source0..24 and chunk0..7. Each28-bit b packs four7-bit ASCII bytes at offsets0/7/14/21. Names are32 bytes, NUL-padded and truncated by the host. Patch holds all eight chunks before displaying a name and clears chunk readiness on seed without clearing gesture context. The local3×5 font renders letters, digits, space, `+` and `-`; lowercase renders uppercase and other ASCII renders `?`. Text overlays the group area while source-first held selection remains interactive. The bridge caches/coalesces these200 facts, forwards them only while patch is active, and reseeds them on modal entry. Names neither keep main busy nor precede performance commands, musical clocks or Busy facts. Changed non-label facts interrupt a label seed without waiting for its remainder. Holding a source renders cached text locally without a name/contact round trip.
- kind7 error: a=key | device-sequence<<7, b=bounded reason code. Same local brief failure treatment; no notifications for group errors.

Bridge assigns SDK revisions and maps wire ACK sequence to original device sequence. Delayed facts never sit ahead of performance command dispatch. Feedback queue coalesces latest fact by kind/context; discrete terminal results remain until sent. Model includes actual values and pending intent separately.

## Native workflow

With `AUDIO_SOURCES=()` the existing fixed T-Bone mono input1 path remains available. Catalog mode discovers up to25 Audio sources and preconfigured MIDI instruments inside the unique `[Inputs]` hierarchy, in Live order. Physical inputs, instruments and effects remain on those original tracks and are never cloned. Audio source tracks use Monitor In, Sends Only output and zero sends. Audio destinations resolve Post FX routes through actual source Track identity using Native `RoutingType.attached_object`, rather than display names or a source-by-group helper matrix.

An assignment selects any available combination for subsequent takes. A take captures its source list and each member's destination; changing an assignment cannot retarget an active take. Each source creates a named/colored Audio or MIDI clip within one logical take, admitted and scheduled for the same boundary. MIDI sources have exclusive group ownership and keep their original instrument instances; overdubs in the same group feed that instance together. Capture lanes preserve the source's external MIDI input/channel, keep Monitor Off, and send clip playback to the direct instrument endpoint. Only the current monitor owner's original instrument uses Monitor In. Instrument audio goes through one explicitly marked shared Audio receiver under that group's `[Remote]` subgroup, then through the group's mixer and effects. Unpatching does not interrupt accepted layers or surrender ownership; Clear releases the original source to Sends Only and Monitor Off. The remembered selection remains, and a new Begin or monitor action can reacquire it. Instrument racks and MIDI effects before the instrument are currently unavailable with explicit diagnostics; they are never silently bypassed. Accept, Next, Retry and Cancel apply to the whole bundle. They preserve previously accepted clips. Native calls are sequential, not an atomic Live transaction; uncertain member starts/finishes are observed and bounded rather than replayed.

Prepared Audio recording lanes themselves carry live input through Monitor Auto with controller-owned arms. One group owns monitoring at a time. Current/next take handoff can briefly monitor both paths, as accepted in the hardware trial. No source-by-group monitoring helper matrix is needed. Source identity and selection are Set-local metadata; actual clips and routing remain Live-owned. Native Track data serializes during a real Set save. Metadata-only changes do not create a save prompt or make clean Cmd+S write a file; actual routing changes do. The matching Live adapter must cover this distinction rather than inventing unrelated parameter toggles or automatic saves.

Reuse compatible quiet direct Audio lanes with empty current phrase slots, excluding current/following members, externally armed/playing/triggered/frozen tracks and all subgroup descendants. Four initial lanes per group are a starting inventory; each selected source consumes one lane per take. Keep a whole next bundle ready. With automatic expansion enabled, missing capacity is added just before the rightmost direct `[Remote]` subgroup. The user accepts the known audible insertion cost for this overflow. Existing lanes are reused on later phrase rows without changing previous clips. There is no shared reserve, live track movement or archiving fallback.

Maintenance is a separate bounded callback workflow with actual readiness validation. Prepare the next destination bundle before launch and while recording. Track creation and source routing advance in bounded steps. Monitoring writes act on retained owned take/reserve lanes and disable old live-input paths before enabling replacements. Do not scan the graph or create/route in the ready command path. Respect Native implicit parent routing and actual offered identities. Preserve current selection after creation with the tested SelectionRestoration helper. Cooperative callbacks do not make a Native call asynchronous. Before an overflow bundle needs synchronous Audio-track creation, Live publishes one fresh allocation ticket and returns to its event loop. Existing local gestures finish normally. After the device has drawn busy and sent key58, the bridge rejects new ordinary intents explicitly, drains already-admitted commands and latest parameter values, then forwards that grant. Live validates the still-current ticket and starts preparation in a later callback. One grant covers all missing tracks and routing verification for that bundle. It clears the busy fact when the whole bundle is ready, fails, is cancelled, or its context changes. The overlay preserves local views, take tokens and musical clocks; no program swap or gesture reset is used for this pause. Mode swaps remain blocked from request through clear. A fresh protocol session invalidates historical tickets and never grants an old allocation again.

The initial ungranted request has a ten-second lease that repeated copies cannot extend. After the painted receipt closes admission, Live force-publishes the same ticket about every 500 ms while bundle preparation remains active. A fresh matching observation renews the ten-second callback-liveness window without unlocking input, regranting work or resending unchanged device feedback. Stale generations/sequences and heartbeats arriving after expiry cannot renew it. A long bundle may span multiple windows, but ten seconds without progress still fails closed. Expiry rejects a late grant, shows the existing failure status after contacts lift even if the last heartbeat described a recording, and keeps new command admission closed until Native clears the request or the protocol session resets. Live must cancel an ungranted expired request; disconnects and uncertain allocations are never retried as mutations.

The25-source selector uses two bounded command banks because a25-bit assignment cannot fit a14-bit MIDI command value. Each observation still fits the existing28-bit atomic payload. Main, metronome and status retain their established fields; catalog expansion changes only the patch program and matched host contract.

Recording follows existing UX timing: first accepted loop defines reference through actual leftmost playing loop; Begin/Retry wait for main-loop wrap when possible; finish at next safe bar, later bar if too close; Next accepts at a safe bar and starts its prepared replacement at that same boundary, without waiting for the base-loop wrap. A too-late unissued pair moves together to the following safe bar. No endless countdown on terminal preparation failure, no replay of ambiguously launched clips. Existing accepted clips/Set state must be preserved.

## Delivery gates

Install the helper, Live adapter and all selected device programs together. `--patch-source` is valid only with `--audio-performance`; the normal packaged controller does not acquire patch mode implicitly. Preserve the prior matched runtime for rollback. The patch program uses local semantic interaction, not the earlier raw-contact host-owned patch path.

The build enforces each program's7200-byte budget. Main remains7190/7200bytes and byte-identical to the accepted Audio baseline; its ten-byte margin is not future-feature headroom. The mixed patch program uses3980 code bytes plus1104 heap bytes,5084 total with2116 free; metronome uses3558 total. Modal programs have independent budgets. Lossless storage packing and inlining preserve all established controls; future changes must recheck the compiled budget and stack. Offline joined tests cover patch admission/readiness, mode reseeding, multi-source recording and failure rollback. They do not establish Bluetooth responsiveness or audible routing behavior. New architectural or UX compromises require user involvement.

Live retains the existing channel16 health114..118 heartbeat every500ms and modal permission query109nonce/reply109allow or108deny. With patch enabled, Mode uses the following table after contacts lift and while no recording is active:

| Current program | Short release | Hold at least400ms |
| --- | --- | --- |
| Main | Patch | Metronome |
| Patch | Main | Metronome |
| Metronome | Main | Patch |

A recognized hold never emits a short action on release. Mode is inactive on status. Patch preparation may finish after leaving the screen. The same Live permission query covers either modal target and records which program was requested. Without `--patch-source`, the existing short main/metronome path and reserved hold remain unchanged.

Program swaps reseed the same bridge generation and cached model without discarding Live command state. Actual device topology reconnection establishes a new generation and invalidates ambiguous discrete intent.

A forward gap in the SDK model revision requests one cached model reseed through device CC16/110/19. It does not close ongoing gestures or replay Native discrete commands. Stable state is not repeatedly streamed in full.
